# Error Handling & Resilience Guide

This document defines the unified error handling architecture across both Next.js Server Components and client-side modules.

## 1. Philosophical Principle
Errors are normal operational events. Our goal is to catch them gracefully, log them quietly for diagnostics, and provide our customers with gorgeous, clear, actionable feedback rather than leaving them stranded on white pages or looking at unhandled code logs.

## 2. Server-Side Error Segments
Next.js provides structured layout boundaries `error.tsx` to trap unhandled exceptions at runtime.

When a server-side fetch fails or an unexpected exception is thrown during rendering:
1. The surrounding layout remains functional (e.g., Navbar, Footer).
2. The specific child route is replaced by the custom `ErrorState` component.
3. The component displays an organic illustration, a localized error description, and a "Try Again" trigger to reset the boundary context.

```typescript
'use client';

import { useEffect } from 'react';
import { Button } from '@/shared/components/ui/Button';

export default function ErrorBoundary({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    // Log the error to third-party reporting service
    console.error('Server exception trapped:', error);
  }, [error]);

  return (
    <div className="flex flex-col items-center justify-center min-h-[400px] text-center p-8 bg-rice-white/50 backdrop-blur rounded-2xl border border-gold/10">
      <h3 className="text-xl font-bold text-primary mb-2">خطایی در برقراری ارتباط رخ داد</h3>
      <p className="text-gray-600 mb-6 max-w-md">متأسفانه در دریافت اطلاعات از شالیزار مرکزی با مشکل مواجه شدیم.</p>
      <Button onClick={reset} variant="primary">تلاش مجدد</Button>
    </div>
  );
}
```

## 3. Client-Side API Error Catching
When executing mutations or fetches with Axios and TanStack Query, errors are handled at the interceptor level:

- **401 Unauthorized**: Clears user session context, wipes client stores, and triggers global login modals.
- **403 Forbidden**: Displays clean "Access Denied" alerts.
- **422 Validation / Zod Errors**: Form inputs are highlighted with real-time error messages generated by React Hook Form.
- **500 Internal Server Error**: Activates general recovery states without exposing actual server trace logs.
